# Сборка Backend, Agent и Catalog

## Цель

Собрать локальную рабочую копию приложения из текущего Agent №2 и переданных модулей Backend №1 и Catalog/RAG №3, используя актуальные файлы `datasets/` и оставляя запуск моделей на сервере.

## Решения

- Текущая папка `backend/app/agent/` остаётся основой: рабочие QueryParser, LLMClient, StateManager и AgentOrchestrator не заменяются файлами из других архивов.
- FastAPI и хранение сессий подключаются из `FixTim-hotel-backend-api.zip`; демо-ответы AgentService заменяются одним общим экземпляром AgentOrchestrator и CatalogGateway.
- Catalog/RAG-код подключается из `FixTim-hotel-rag-data.zip`. Архивные `data/demo` не становятся источником истины: для гостиниц используется более новый `datasets/hotels-russia-for-agent.csv`, а транспорт импортируется из актуальных CSV в `datasets/`.
- Конфликт `backend/app/catalog/rag/embeddings.py` решается сохранением текущего BGE-M3 Embedder на исходном пути и размещением интерфейса/адаптера Catalog в `rag/provider.py`. Индексатор и Retriever используют адаптер, который вызывает текущий Embedder и `OLLAMA_URL` из окружения.
- Каталогические записи нормализуются на границе Catalog → Agent. Неизвестная цена остаётся `None`; при бюджетном поиске такой отель может быть показан только с явной пометкой, что соответствие бюджету не подтверждено. Неизвестные обязательные удобства не считаются выполненными.
- `is_demo` означает синтетическую запись. Реальные справочные данные помечаются `is_demo=false`, при этом цена и доступность остаются неизвестными, если источник их не содержит.
- RAG над полями гостиниц называется поиском по описаниям/характеристикам; он не выдаётся за отзывы. Без отдельного датасета отзывов `retrieve_reviews` возвращает пустой список.
- HTTP-ответ сохраняет прежние поля Frontend и добавляет транспорт и подробные поля гостиницы.
- Никаких подключений/изменений сервера, установки Ollama или локального вызова модели. Проверку и запуск пользователь проведёт на сервере завтра.

## Не входит

- Реальные бронирования, актуальные цены/наличие, отзывы, климат и поездки поездом без соответствующих источников.
- Создание нового LLM-клиента или замена модели.
- Перезапись или автоматическая синхронизация с сервером.

## Поток

Frontend → FastAPI → SQLite SessionService → существующий AgentOrchestrator → адаптер Catalog/Agent → CatalogGateway → актуальные локальные датасеты и (если построен индекс) BGE-M3/FAISS → AgentResponse → совместимый ChatResponse.
